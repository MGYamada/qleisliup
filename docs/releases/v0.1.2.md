# qleisliup v0.1.2

Prepared source release for the adopted Rust/Lean/Python environment boundaries
and fixes for lifecycle issues #7–#9. This version update does not publish a
registry package, GitHub release, tag, or production distribution.

## Changes

- Resolve Rust/Lean implementation dependencies when producing native bundles;
  keep Python wheels and project-local uv environments separate.
- Document exact Python environment records, explicit handoff of the selected
  compiler, and pending upstream kernel/wheel compatibility gates.
- Add a reusable restricted-PATH guard for 25 Rust, Lean, Python, environment
  manager, and native build-tool names. Detect invocations even when a scenario
  ignores the developer tool's failure.
- Exercise the guard in the existing six-job CI matrix and include the helper,
  its checks, and the environment policy in source packages.
- Create owned directories with mode 0700 under permissive umasks; reject
  existing group/world-writable homes, state, and lifecycle parents (#7).
- Recover crash-left atomic state files through bounded, descriptor-relative
  cleanup and randomized exclusive temporary names (#8).
- Use one canonical generation-name rule for TUF loading and cleanup, retaining
  active-generation inode and case-alias protection (#9).

Manager commands, selection precedence, JSON schemas/pin formats, dependency versions,
and the verification authority remain unchanged. Cargo.toml supplies version
0.1.2 to both qleisliup and qleisliup-init. Existing unsafe directory modes and
noncanonical TUF generation pointers now fail closed and require explicit repair.

## Source installation

From this checkout, with Rust 1.85 or newer and the native build prerequisites
described in [README](../../README.md):

```sh
cargo install --path . --locked
qleisliup --version
qleisliup-init --version
```

These commands report `qleisliup 0.1.2` and `qleisliup-init 0.1.2`. Registry
installation of 0.1.2 requires separate publication; the README retains the
published 0.1.1 registry example until then.

## Distribution and validation boundary

Production URLs and the initial trusted TUF root remain unconfigured. Native
manager checks use local fixtures; they do not establish real Qleisli/qargo
bundle compatibility, native Lean readiness, or Python wheel compatibility.
Cargo installations still require explicit proxy setup and remain externally
owned for self-update purposes.

Local macOS ARM64 validation passed on Rust 1.85.0 and stable Rust 1.98.1:
debug/release builds of both binaries, all 173 test executions per compiler,
formatting including native fixtures, clippy with warnings denied, CLI/runtime
guard checks, and offline source package verification. The Unix-socket fixture
required testing outside the local execution sandbox. Both binaries report
0.1.2. Both 52-file source packages preserve the locked graph and final Rust
sources. The six-job CI matrix validates the three initial hosts separately;
this local record covers macOS ARM64 only.

See the [validation record](../implementation-plan.md),
[environment policy](../environment-dependencies.md), and
[publishing procedure](../publishing.md). Actual publication and production
activation remain separate operations.
