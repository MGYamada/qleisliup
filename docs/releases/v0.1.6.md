# qleisliup v0.1.6

The README disclaimer uses the same non-affiliation wording, tool names, and
Rust and Cargo trademark attribution as the [qlirgo v0.2.0 README](https://github.com/MGYamada/qlirgo/blob/v0.2.0/README.md).

The Cargo package and both executables use version 0.1.6. For prerequisites
and checkout instructions, see the [source installation guide](../source-installation.md).

Security updates cover the TLS certificate stack, URL handling, Zstandard
bindings, and tar archive parsing, along with RustSec warnings for Tokio and
rustix. Updating `futures-util` removes the unmaintained `pin-utils` dependency.

The manager supports the Qleisli 0.3.0 and qlirgo 0.2.0 pair through schema 2
manifests and receipts. The new `qlirgo` and `qlinties` proxies use the selected
toolchain's native kernel. Schema 1 qargo releases and existing proxy layouts
continue to work.

## Local validation

Rust 1.85.0 and stable Rust 1.99.1 passed locked debug builds, 180 test
executions per compiler, formatting, Clippy with warnings denied, and CLI smoke
checks on macOS ARM64. The test suites ran outside the local sandbox to allow
the Unix socket fixture. The source package inventory check included both
executable entry points and these release notes.

Cargo 1.85.0 resolved the locked dependency graphs for macOS ARM64, macOS x86_64,
and Linux x86_64 musl. The selected crates' declared minimum Rust versions all
fit the project's Rust 1.85 minimum. Cargo-audit 0.22.2 reported zero
vulnerabilities and zero warnings across 216 locked dependencies against RustSec
database revision `8b75c83c3c9142dd18e93d75b8d895a13d285861`.

### Formal release pair

The macOS ARM64 local link used the crates.io Qleisli 0.3.0 compiler built with
Rust 1.85.0, the official Qleisli 0.3.0 native kernel, and the official qlirgo
0.2.0 binary bundle. Both archives matched the upstream SHA-256 checksums.
[Qleisli release](https://github.com/MGYamada/Qleisli/releases/tag/v0.3.0) · [Qlirgo release](https://github.com/MGYamada/qlirgo/releases/tag/v0.2.0)

Direct and proxied compiler and qlirgo checks returned identical JSON for the
nonempty qlinties smoke qrate. Qlirgo lint passed through its bundled `qlinties`
sibling. Both checks and the lint passed with developer tools trapped on PATH.
Authenticated installation uses isolated TUF fixtures for validation.
Production distribution and real toolchain execution on the other supported
hosts remain separate acceptance scenarios.
